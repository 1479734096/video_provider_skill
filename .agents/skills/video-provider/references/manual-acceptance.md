# 手动验收

本流程用于新机器、客户端或模型的媒体输入核对。分别确认媒体取得、媒体进入当前模型和具体问答，沿用当前模型。

## 准备媒体

选取一条待验收模型不熟悉的真实视频，截取包含明确动作及声音的短片段。先检查 CLI 返回的轨道、时长、尺寸和实际区间，再将 MP4 复制到中性命名的独立目录，例如 `clip.mp4`。

在客户端的独立会话中只提供该文件和下面的问题。不要提前提供标题、字幕、来源说明、预期答案或抽出的关键帧。提示词中的路径替换为当前机器上的实际绝对路径。

## 第一步：MP4 原生读取

将下面提示词交给当前模型，或通过当前客户端的原生视频附件入口上传同一 MP4：

```text
请使用当前会话的原生视频工具读取 <clip.mp4 的实际绝对路径>。

只依据该文件，按片段内时间描述开头、中间和结尾的具体画面、动作先后及物体相对位置。
请说明实际听到的语言，给出一句听清的短句，并描述背景声音。
如果没有收到声音或没有原生视频输入，直接说明实际情况。
请列出所用媒体工具及实际读取的文件路径。
不读取相邻文件、字幕或现成答案，不联网，不抽帧，不调用其他模型或 Agent。
```

保留实际工具读取记录、可见的媒体附件类型和模型原始回答。人工播放 MP4，对照至少两处具体画面和动作先后，再对照声音。只有读取路径成功，不算理解验收。

## 第二步：必要时单独读取 WAV

若第一步没有声音，可用 CLI 对该片段执行 `fetch <本地片段> --full --audio-format wav`，继续在同一会话中提供返回的 `audio_path`：

```text
刚才 MP4 的同一段音频已独立导出：<同一片段 WAV 的实际绝对路径>。

请用当前会话支持的原生音频工具或附件入口读取，报告实际听到的语言、
一句听清的短句和背景声音。不要从画面文字推断声音，也不要调用外部 ASR 或模型。
如果当前客户端不支持音频输入，请报告工具或接口的实际限制。
```

人工播放 WAV 核对后，将结果分别记为“视频画面”“MP4 内声音”“独立 WAV 声音”，避免把独立音频通过写成 MP4 音轨已自动进入模型。

## 验收后的记录

记录当前客户端版本、当前模型、输入入口、实际文件和分析时间范围，以及两处画面答案、一处动作顺序和声音答案是否与文件一致。若模型答错而实际媒体正确，记录为理解错误；如果原生入口没有传递媒体，记录为客户端输入限制。

原视频时间使用 CLI 返回的 `actual_range.source_start_ms + 片段内时间`。来源信息由验收者留存，不提前提供给待验收模型。
