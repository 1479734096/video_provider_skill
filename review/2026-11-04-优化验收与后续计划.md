# video-provider 1.0.1 优化验收与后续计划

日期：2026-11-04。本轮按用户授权实施，并自动执行真实媒体对照、边界验证和分发包运行验收。

结论：Windows 供片链路完成本轮验收。远程片段从两轮视频编码改为一轮，复用当次取流信息；三组实际请求均比旧版快。精确区间、来源清晰度、字幕与缓存行为保持一致。文件体积有所增加，macOS/Linux 留待实机验证。

源码包含 Skill 入口、CLI、安装说明、客户端说明、手动验收流程及项目现有 MIT LICENSE，共 6 个文件。原 1.0.0 包、原始脚本、历史媒体与用户已有的 Git 改动保留；未执行 Git 写操作。

本轮实现：

1. **单次编码**：通过 yt-dlp 的 FFmpeg 下载器输出参数，一轮完成区间裁剪、缩放和 H.264/AAC MP4 编码。远程片段跳过后续 `convert()`；本地与完整来源缓存仍转换一次。
2. **元信息复用**：本次解析结果写入调用专属的临时 info-json，通过 `--load-info-json` 下载；失效回退复用下载器机制。文件与运行时临时目录随调用结束回收。
3. **减少重复查询**：Skill 对明确区间直接调用 `fetch`；需要决定分 P、区间或全片覆盖时才先 `inspect`。依赖预检在会话首次使用或依赖报错时执行。
4. **减少整文件复制**：远程完整来源验证后直接移入缓存；本地用户原文件继续保留。
5. **提前校验与成品检查**：非法时间、参数冲突和无效显式分 P 在联网前报错；兼容片段检查编码、像素格式、MP4、尺寸、音轨及时长。远程片段使用 `h264-aac-v2`，完整来源缓存继续复用。

CLI 仍使用 Python 标准库与已有 yt-dlp、FFmpeg/ffprobe。验收中使用本机已有的 NumPy 做音频波形对齐、Pillow 拼接代表帧，这两者不进入产品依赖。

| A：`BV13eDABsEU6` | 4.125–14.500 秒，AV1/AAC，`100026+30280` | 9.837 秒 | 7.431 秒 | 1080×1440 | 5730366 → 6580497 字节，+14.8% |

三条交付版记录分别减少 24.5%、16.9%、27.1% 的总耗时。首次优化试跑分别为 9.594、5.844、6.897 秒；修正临时目录管理后，对最终源码另行复验，表中采用复验结果。网络与系统缓存会影响总时长，因此保留两轮原始记录。

编码次数和解析路径通过生产代码及上游实现核对，耗时、格式和体积来自实际 CLI 运行。去掉前一级有损编码后，文件增大；本轮保留画质与最终编码参数，使用当前客户端预算缩短片段来控制输入体积。

本轮发现并修正两项实际问题：

1. 最初的像素格式检查错误拒绝 `yuvj420p`。已改为按 8 位 4:2:0 接受有限范围与全范围表示，并返回 `color_range`。依据为 [FFmpeg 像素格式定义](https://github.com/FFmpeg/FFmpeg/blob/n9.0.1/libavutil/pixfmt.h)。修正后真实全范围片段及缓存复验通过。
2. 强制结束单文件下载器后，其解包运行库留在共享临时目录。现为每次外部命令分配调用专属目录，随 Provider 结束回收；复验没有遗留进程、运行库或未完成媒体。

清理修复前那次验收留下的 `_MEI` 运行库目录时，自动审批以 `blocked by policy` 拒绝了删除命令，因此该历史目录仍保留在本轮证据目录内。修复后调用的临时目录为空；正式分发包不包含运行库或这些历史文件。

核心证据文件包括 `summary.json`、`functional.json`、`profile-check.json`、`full-range-fixed.json`、`timeout-check-final.json`、`package-check.json`。本轮验证的是供片格式、内容区间、缓存和进程生命周期；模型原生输入及理解继续沿用用户此前已确认通过的验收记录。

## 评价

本轮改动值得保留：减少一代有损编码和重复平台解析，实际输出保持来源清晰度、正确区间及音轨；源码仍为单文件标准库编排。完整来源没有为优化片段而改变编码。

需要关注的是输出体积增加，以及缓存命中仍需联网等待。前者保持当前质量优先策略；后者可以作为下一个明确的性能目标。

Windows 本轮运行通过。WSL 查询返回 `Wsl/0x80070422`，服务无法启动，本轮没有执行 Linux 实测或更改系统服务；macOS 也尚无实机结果。

## 下一步顺序

| 优先级 | 下一步工作 | 具体修改或验收范围 |
| --- | --- | --- |
| P1 | 补齐 macOS/Linux 实机回归 | 在可用环境验证工具发现、带空格和中文的路径、FFmpeg 输出参数、片段与字幕、超时/取消后的进程组回收；根据真实失败修复，不预先增加平台分支 |
| P2 | 可选离线缓存模式 | 默认在线确认最高可用格式；显式 `--offline` 只读取已完成媒体及公开来源描述，返回缓存画质和实际范围。保存来源身份、时长与别名映射，不持久化签名播放地址或凭据；缓存缺失给出明确结果 |
| P3 | 评估批量抽帧 | 对短片尝试一次解码按 PTS 选帧，长视频稀疏采样保留随机定位。比较真实耗时后决定策略，覆盖可变帧率与实际帧时间映射，保持用户明确选择图片模式的边界 |

本轮不实施这三项后续工作。继续使用当前画质与编码参数；客户端输入体积超限时优先缩短片段。
